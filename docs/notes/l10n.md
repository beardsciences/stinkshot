# Localization

Framework landed Nov 8 2026. English is the only shipped language; the rest is plumbing so
strings can be converted in parallel and translations added later.

## Choice: compact Rust tables, not Fluent

- Strings are `match` arms in plain Rust (`crates/app/src/l10n/<lang>/<group>.rs`). The
  compiler turns them into static data: zero startup cost, no parser, no new crates.
- Fluent (`fluent-bundle` + `unic-langid` + `intl-memoizer`) adds roughly 300-500 KB, parses
  `.ftl` at startup, and returns owned strings on every lookup. Stinkshot needs plain strings
  plus `{name}` placeholders; plurals are rare enough to handle with separate keys
  (`history.count.one` / `history.count.other`).
- Tradeoff: translators edit `.rs` files instead of `.ftl`. Each file is a flat list of
  `"key" => "text",` lines, so it is still simple to hand off. If a real translation effort
  starts, a generator from `.ftl` or `.po` into these tables is a small follow-up.

## API

- `use crate::l10n::tr;` then `tr!("settings.theme")` gives a `&'static str`.
- `tr!("history.empty.count", n = count)` fills `{n}` and gives a `String`.
- `l10n::lookup(key)` is the function behind the macro, for keys held in a table
  (see `l10n::CHOICES` in the Language setting).
- Missing keys fall back to English, then to the key text itself (warned in debug builds).
- `l10n::apply(&config.general.language)` sets the language. Called after `Config::load` in
  `shell::run_app` and when the Language setting changes. Most text updates next frame; the
  tray menu is built once, so it changes on restart.

## Groups and files

One file per group so parallel converters never touch the same file:

| Group | Prefix | Code | Strings file |
|---|---|---|---|
| settings | `settings.` | settings_ui.rs | `l10n/en/settings.rs` |
| history | `history.` | history_ui.rs | `l10n/en/history.rs` |
| overlay | `overlay.` | overlay/** | `l10n/en/overlay.rs` |
| shell | `shell.` | shell.rs, shell/, tray.rs, toast.rs, pin.rs, record_ui.rs, errors.rs, actions.rs, cli.rs output, everything else in crates/app | `l10n/en/shell.rs` |

## Converting a string

1. Pick a key: `<group>.<area>.<name>`, lowercase, dots and underscores
   (`settings.capture.loupe`, `settings.capture.loupe.desc`).
2. Add `"key" => "Text",` to `get` in the group's file and `"key",` to its `KEYS`. The
   `l10n::tests::keys_are_grouped_and_unique` test checks prefix, duplicates and that both
   lists agree.
3. Replace the literal with `tr!("key")`. Labels take `&str`, so it drops in for
   `ui.label`, `on_hover_text`, `setting_row`, `RichText::new`, `MenuItem::with_id` and so on.
4. `format!("Press {k} to capture")` becomes `"Press {k} to capture"` in the table and
   `tr!("history.empty.press", k = hotkey)`.
5. Keep copy rules: Title Case labels, one short sentence-case description line.

Do not translate: log messages, `.context(...)` error chains that only reach the log, IDs and
salts, config values, file names. CLI `--help` text from clap stays English for now.

## Checker

`scripts\check-strings.ps1` (add `-Verbose` to list each literal with its line) runs the
ignored test `crates/app/tests/check_strings.rs`. It flags string literals with a letter
passed directly to `label`, `button`, `heading`, `small`, `strong`, `on_hover_text`,
`hint_text`, `selectable_value`, `checkbox`, `selected_text`, `RichText::new`,
`MenuItem::with_id`, `setting_row`, `toggle_row` and similar, and prints counts per group
and file. It exits nonzero until everything is converted. Set `CARGO_TARGET_DIR` first.

- Allow a one-off with `// l10n-ok` on the literal's line.
- Allow a literal everywhere (product names, format names) in `scripts/strings-allow.txt`.
- It stops scanning a file at its first `#[cfg(test)]`, and misses literals built with
  `format!` or held in variables first; those still need a human pass.
- The non-ignored `scanner_flags_and_skips` test keeps the scanner honest in CI.

## Pseudo-localization

Language setting "Pseudo" or env `STINKSHOT_PSEUDO=1` swaps every looked-up string for an
accented, bracketed, ~35% longer version (`[Ŧĥéɱé ~~]`). Unconverted literals stay plain
English and stand out; clipping shows where the brackets go missing. Placeholders like
`{n}` are kept intact.

## Adding a language

1. Copy `l10n/en/` to `l10n/<code>/` (e.g. `de`) and translate the strings; keys may be left
   out and fall back to English. Keep `KEYS` only in `en`.
2. In `l10n/mod.rs`: add a `Lang` variant, its `from_u8` and `code` arms, add it to
   `SHIPPED`, and add a per-language arm in `tr` that tries `<code>::<group>::get` before
   English (mirror `english`).
3. Add `("de", "settings.language.de")` to `CHOICES` and the label key to the settings group,
   written in the language's own name ("Deutsch").
4. "System Default" matches the Windows locale's primary subtag (`de-AT` picks `de`).

workers.rs, hotkeys.rs, ui_hotkey.rs, theme.rs (On/Off), logo_anim.rs (About version and
tagline), filedialog.rs (Save As title and filter names). The checker reports 0 for the shell
group.

- `errors::LOG_HINT` is now `errors::log_hint()`.
- Hotkey problem texts embed a looked-up phrase (`shell.hotkey.phrase.*`) through `{phrase}`,
  so `hotkeys::ErrorKind::of` still finds the kind in translated text. Keep `{phrase}` in
  translations of `shell.hotkey.invalid` / `duplicate` / `in_use` / `not_registered`.
- `workers::NO_OCR_HELP` stays an English const for history_ui, settings_ui and overlay;
  shell code uses `shell.ocr.none.body`. Those groups should switch to
  `tr!("shell.ocr.none.body")` (any group may look up a shell key).
- `ui_common::rect_button` shrinks its label (down to 10 px) when it does not fit; pseudo
  "Copy Text" in the toast ran past its button before.
- Left in English on purpose: window titles ("Stinkshot History", "Stinkshot Settings",
  "Stinkshot Trim"; `focus_window` finds windows by title), key names (Ctrl, PrtSc, Esc),
  units (KB, MB, FPS), clap help text, error strings that only reach the log or are matched
